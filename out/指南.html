项目简介

夜织 CialloForge 是一个面向成人向创作的本地生成工具，把两条流水线打通：

  • 文本：角色卡 → 分幕 beat → 热度分级词库 → 声线改写 → 成稿（Markdown，含角色卡与配图提示词附录）
  • 绘图提示词：角色 × 场景 × 六种目标格式（SDXL / Pony / NovelAI / Midjourney / ComfyUI / 通用包）

四条设计原则

  • 全员成年锁 18+ —— 角色卡必须显式声明 age >= 18 且 ageLock: true，

卡层 / 引擎层 / 文本层三道闸拦截；提示词负向固定包含幼态排除词。

规则是「ageLock 优先于造型词」：成年角色写娇小、白发、幼态妆属于造型选择，放行；

只有年龄字段未成年、或年龄缺失且幼态体型词占主导时才拒收。

  • 零依赖全离线 —— 只用 Node 内置模块（http / fs / child_process），

无任何网络请求，node_modules 不存在也能跑，断网可用。

  • 可复现 —— 同一输入（场景 / 卡司 / 热度 / 节奏 / 种子）逐字节一致，

这也是它能写回归测试的前提。

  • 界面与命令行同源 —— 后端端点直接调用引擎，不复制任何生成逻辑，

所以图形界面与 CLI 的输出必然一致（自检里有一条专门验证：同一输入 3753 字符完全相同）。

两条流水线

一、文本流水线

场景(scene) ─→ 幕(act) ─→ beat(type + 模板) ─→ token 解析 ─→ 声线改写 ─→ Markdown
                                  ↑
                          角色卡(cast) / 热度(heat) / 节奏(pacing) / seed
  • beat 类型：sensory 感官 / action 动作 / pressure 施压 / climax 高潮 /

release 释放 / afterglow 余韵 / interior 内心 / dialogue 台词

  • 热度 1-5：1 克制 → 3 缠绵（身体描写，无器官名词）→ 5 露骨（全词库开放）。

池子里每条词带 min 字段，低于该热度不会被选中；无候选时只放宽到该池最低档，

绝不回退到全池（这条是早期 bug 的教训）

  • 节奏档：slow 慢燃 / balanced 均速 / fast 快进 / pwp 直入，

用 word 数倍率 + 铺垫 beat 跳过率控制

  • 字数控制：目标字数 × 节奏倍率，不足时循环补 pressure/action/climax/afterglow/sensory
  • 声线：台词种子经过寄存器管线改写 —— truncate 压短 / stutter 结巴 /

particle 助词 / echo 口气词前插 / breath 停顿符 / terminal 收束。

同一句「你要是疼就说，别忍着」在 10 个角色口中是 10 种写法

二、提示词流水线

角色卡(appearance.tags + body + negative + loraAnchors)
   × 场景(tags + camera) × 姿势(heat × kinkFamily) × 评级(safe/suggestive/nsfw/explicit)
   → SDXL / Pony / NovelAI / Midjourney / ComfyUI / 通用包

输出内容：正向前缀（评级）→ 质量词 → 年龄锚点 → 造型标签 → 身体细节 → 场景 →

姿势 → 双人标记 → 自定义 → LoRA 权重；负向固定含基础瑕疵词 + 幼态排除词 + 角色专属负向。

年龄锁机制（三道闸）

  • 卡层：age 必须是数字且 >= 18，ageLock 必须为 true。缺失或不达标 → 校验失败
  • 引擎层：compilePrompt 遇到未成年卡直接 throw；gateCharacter 供外部复用
  • 文本层：scanText 扫幼态词表。规则是 ageLock 优先于造型词 ——

成年角色写「娇小 / 白发 / 幼态妆 / 150cm」只是造型选择，放行并标记 review；

只有「年龄字段是未成年」或「无成年锚点且幼态体型词占主导」才 reject

validate --gate 会现场构造一张 17 岁卡与一段幼态文本，验证两处都被拦下。

扩展

加角色：往 data/characters.json 的 characters 数组追加一张卡，字段照着现有卡写。

voice.register 必须已存在于 voice-registers.json，否则校验报错。

加场景：往 data/scenes.json 追加，acts[].beats[].type 用 8 种类型之一。

beat 模板里可用 token：

token含义
{A} {B} / {who} {target}主导方 / 对方的名字
{loc} {prop} {sensory} {light}场景地点 / 道具 / 气味 / 光源
{body} {garment} {fluid} {verb}身体部位 / 衣物 / 体液 / 动作词（按热度分级）
{reaction} {aftermath} {intent} {intensityWord}反应 / 余韵 / 内心 / 强度词（按热度分级）
{voice} {line}声线侧写 / 当前台词
{mood} {moodColor} {kink}氛围词 / 氛围注脚 / 癖好注脚

加热度档 / 词库：data/prose.json 里改 heat、bodyPart、fluid、reaction 等族，

每条带 min（生效最低热度）与 weight（抽样权重）。

CialloForge · 夜织

A local, offline generator for adult fiction and image-generation prompts.
16 original adult characters · age-locked 18+ · zero dependencies · pure Node.js · no network access.
⚠️ 18+ only. This tool is built for adult creative writing. All characters are original
fictional adults (ages 19-34). It does not generate or fetch images — it produces text and prompts.

What it is

CialloForge joins two pipelines behind one character database:

  • Text — character card → act/beat plan → heat-tiered phrase library → voice-register rewriting → a finished story (Markdown, with character sheets and prompt appendices)
  • Image prompts — character × scene × six target formats (SDXL / Pony / NovelAI / Midjourney / ComfyUI / generic)

No LLM is involved. Text is assembled programmatically from structured templates, a

heat-graded phrase library, and per-character speech registers. That is what makes it

offline, deterministic and testable — and it is also why long-form repetition needs

explicit management (documented in the known-limitations section).

Design principles

  • Adult age lock (18+) — every character card must declare age >= 18 and ageLock: true.

Three gates enforce it: card validation, engine refusal, and text scanning. Prompt negatives

always include minor-coded exclusion tags.

The rule is *ageLock beats styling words*: an adult character described as petite, white-haired

or with a youthful makeup style is a styling choice and passes; only an underage age field, or a

missing age combined with child-coded body terms, is rejected.

  • Zero dependencies, fully offline — Node built-ins only (http, fs, child_process).

No network requests. Runs with no node_modules directory at all.

  • Reproducible — the same inputs (scene / cast / heat / pacing / seed) produce byte-identical

output. This is what makes regression tests possible in the first place.

  • One engine, two front ends — the HTTP endpoints call the engine directly and duplicate no

generation logic, so the GUI and the CLI cannot disagree. A self-check asserts it: the same

input produced 3753 identical characters through both paths.

8. 常见问题

Q：为什么 low heat 的正文里没有直白词？

A：prose.json 里每条带 min 字段，低于该热度不入选。设计如此，不是 bug。

想让 heat 2 更露，把对应条目的 min 调低。

Q：同 seed 会不会重复？

A：同 seed 逐字节一致（这是可复现性的前提）。想要变化就换 seed，或者用

--seed 1,2,3 批量出多篇。

Q：字数总是超出目标？

A：目标是下限，引擎按 beat 逐段累加到超过即停，最后一拍可能冲过头。

要更贴近就把 --words 调小，或者用 pwp 档。

Q：角色卡能写真实人物吗？

A：不建议。现有 10 张全是原创设定，改写时保持原创。

Q：支持哪些绘图模型？

A：SD1.5/SDXL/Pony/Illustrious 系（sdxl/pony）、NovelAI V3/V4（novelai）、

Midjourney v6+（midjourney）、ComfyUI 任意底模（comfyui，改 params.model 即可）。

Flux 系把 sdxl 目标里的质量词换成自然语言短句即可，标签结构仍可用。

开发手记 · 夜织 CialloForge

记录这次从零到 23/23 自检通过、45 项测试全绿的过程，重点是踩过的坑。都是实测出来的，不是设计时想到的。

1. 交付形态是怎么定的

需求是一句话：「按你的想法做一个完整的项目」。所以项目必须能独立跑、能验收、能被别人接手改。

选了三条硬约束：

约束理由
零依赖纯 Node不装包、不联网、node bin/ciallo.js 就能跑
seed 全驱动同 seed 逐字节复现，否则没法写回归测试
年龄锁走三道闸卡层 / 引擎层 / 文本层，任一层漏了都能被测试抓到

文本引擎没有调用任何 LLM —— 走的是「模板 + 分级词库 + 声线寄存器」的程序化路线。

好处是离线、确定、可测；代价是长文的重复度需要专门治理（见第 4 节）。

2. 十个真 bug 与修法

2.1 token 只解析一层，变量名漏进正文

{A}、{prop} 这类 token 出现在池子条目内部（例如 {loc}的光线只剩{prop}那一处），

第一层解析把池子条目填进去之后，里面的 token 就不再处理了。正文里直接出现 {A}。

更坑的是 sanitize() 里那句「清理残留 token」的兜底正则 [{][^{}]*[}] —— 它把

{A} 当成残留一并删掉，于是正文变成「把翻过去，从后面重新压上来」这种缺主语的句子，

看起来像文笔问题，其实是解析问题。

修法两条：

  • resolve() 改成循环解析（最多 6 轮，收敛即停）
  • 残留清理只认多字符 token（[{][^{}]{2,}[}]），单字母变量不碰

2.2 {A} / {B} 没有注册解析器

RESOLVERS 里有 who / target，却漏了 A / B。未知 token 被原样保留，

所以 {A} 一路活到输出。补上两个键即可 —— 这类 bug 的特征是「有的句子正常、有的缺名字」，

因为只有走池子分支的句子才会碰到。

2.3 heat 在递归解析时掉回默认值

resolve() 早期版本在递归时会 makeScope({ rng: val }) —— 传进去的是个字符串，

但函数签名已经改成对象解构，于是 heat 取了默认值 3。

后果：给 heat 2 的场景生成了 {body} → 甬道深处 这种 5 级词库内容。

这个 bug 危险在于不出错、只出错内容。抓到它靠的是那条「heat 2 不出现器官名词」的断言。

2.4 池子无候选时回退整池

分级过滤写成了：

let cands = pool.filter(x => x.min <= heat);
if (!cands.length) cands = pool;   // ← 毒药

当某热度档一条都没有时（例如 heat 2 对上全是 min≥3 的词库），直接放开整个池子，

高热词全线漏出。改成「只放宽到该池的最低档」，永远不会跨档。

2.5 补写循环整段复用旧句

字数不够时会循环补 beat。但 uniqueKey 的去重集合是每次 makeBeatScope 新建的，

循环里每次都是新的 Set，于是同一句被抽出来好几次，正文出现连续重复段。

修法：

  • 把「已用句子」集合提升到整篇作用域（ctx.usedGlobal），逐 beat 继承
  • 句子抽空就返回空串，循环靠 emptyStreak 退出，不再空转

顺带把池子从 6-8 条扩到 12-16 条，保证 2000 字量级不会中途枯竭。

2.6 命名空间 token 查不到键

词库里写了 {heat:intensityWord}（带命名空间前缀），但解析器只拿冒号前的部分查表 ——

heat 不是解析器，于是整个 token 保留，最后被残留清理删掉，输出变成

「节奏从试探变成，旧毛衣袖口被撞得挪了位置」。句子里那个空位是读得出来的伤。

修法：查表时先试完整名，再退回冒号后的名字。同时给测试加了「空插槽」检查

（变成， / ，。 / 段首标点 / 连续空格），这类伤以后会被自动抓到。

附带经验：断言不能写太宽。第一版空插槽检查把 的， 也列进黑名单，
结果「练出来的哦，」这种正常中文全部报错 —— 断言要盯结构特征，不能盯常见字串。

2.7 性别代词在混合卡司下打架

场景模板里写死了「她」。当场景主角是男性角色（罗砚）时，输出变成

「她的手从膝盖一路往上……她说这话的时候」，而这段描写的其实是男性角色。

治理过程分三步，前两步都是错的：

  • 全局正则替换：把所有「她」换成 {pronA} —— 会误伤指代对方的代词
  • 按出现顺序判定：默认第一个代词归 A、其余归 B —— 遇到「她（=对方）」开头的句子就错
  • 按子句归属判定（最终方案）：
  • 先做 beat 级投票：整段文本与 A/B 的特征词表比对，命中权重大的一方拥有多数代词
  • 再做代词级修正：某个代词所在子句明显偏向另一方（差值 ≥ 6）时单独改判
  • 子句无判别信息时，男女搭配按性别匹配，同性别沿用段级判定
  • 剩 2 处启发式确实无法判断的，写进显式修正表（带注释说明理由）

同时把散文池里的代词全部换成 {A}/{B}（出名字，永不歧义），

并把「作者手写模板的代词」与「引擎抽样段的代词」区分开测试：

前者是创作意图，后者是泄漏。

2.8 场景把服饰和性别绑死了

场景模板里写死的「高跟鞋」「铅笔裙」，在男女向配对下会出现在男性角色身上

（「沈聿的高跟鞋停在原地」）。同类的还有「沈芷的乳肉把沈聿咬得很紧」这种归属错位 ——

{body} / {garment} 默认属于「对方」，但模板写成了「{A} 的动作 + 无归属的部位」。

修法：

  • 服饰词中性化（高跟鞋 → 鞋跟），场景模板一律不写性别绑定服饰
  • 部位/服饰归属显式化：{A}把{garment}解开 → {A}把{B}身上{garment}解开
  • 加了一个审计脚本 fix-pool-attribution.js，用「动作直接落在未标归属的部位上」判定错位，

并把语义正确的句子放进白名单 —— 否则每跑一次都要人工重看一遍

2.9 台词侧写串了声线

台词 beat 的侧写取自「当前角色」的声线池，但早期实现里 A（主导方）和说话人是同一个变量。

男女向配对下 B 开口时，就会写出「沈芷：『啧，安静点。』把问题原样抛回去，用停顿逼对方先开口」——

后半句是沈聿的声线描述。

修法：把「说话人」独立成 {V} 与 scope.V，A/B 保持主导关系不变；

当说话人不是 A 时，侧写改从中性池 dialogueNeutral 抽，不再借用别人的口癖。

2.10 换成男女向后加的角色与配对

原卡池 10 张里只有 1 个男性，场景配对也全是女女。为了让「男女向」成为默认体验：

  • 新增 6 张男性卡（C11 江彻 / C12 沈聿 / C13 陆迟 / C14 谢屿 / C15 周叙白 / C16 裴野），

每人独立声线寄存器（新增 clipped-cold / low-tease / earnest-fast / steady-coach）

  • 每个场景补两个字段：leadGender（A 位性别）+ autoCast（默认两人配对）
  • 引擎按 autoCast 组装卡司；显式 --cast 时顺序即 A/B，不被覆盖；--lead 可临时换主导性别
  • 画廊脚本加了启动自检：卡司必须存在、互不相同、必须是男女组合、A 位性别必须等于 leadGender，

任一不满足直接抛错 —— 让「又变回女同」这种回归跑不起来

a) target: 'all' 没被展开。 前端传 target=all 表示「六种格式都要」，但

compilePrompts 把它当成一个目标名去查表，查不到就静默跳过 → 返回 undefined，

修法：目标与场景都支持 all 展开，未知名字显式抛 400。

Cannot read properties of undefined (reading 'id')，界面白屏。

修法：所有 init*View() 挪进 bootstrap() 成功分支，先有数据再建视图。

  • 从 index.html 抓所有 id、从 app.js 抓所有 $('#x') 引用，做集合比对
  • 最小假 DOM（querySelector/classList/addEventListener/innerHTML）在 vm 里真执行 app.js，

断言启动不抛异常、确实请求了 stats/characters/scenes

  • 断言 fetch 全失败时也不产生未处理的 Promise 拒绝（离线不崩）
  • 断言七个页签容器存在、CSS 无远程 @import

2c. 桌面版（Electron 打包）

需求是「真软件体验」。选了 Electron（原生窗口 + 图标 + 无控制台 + 可安装卸载），

代价是体积 107 MB 且打包需要联网装依赖。三处关键改动：

a) 数据目录必须搬家。 原来 data/、out/ 都挂在项目目录内部（io.js 里

ROOT = path.resolve(__dirname, '..', '..')）。打包后代码在只读的 asar 里，

用户把程序装到 C:\Program Files\ 就写不进去 —— 设置、存稿、导出会全部失败，

报错还很难懂。于是加了 src/util/datapath.js 做四级解析：

CIALLO_DATA_DIR 环境变量 → Electron userData → exe 旁有 portable.marker → 项目目录

io.js 拆成「只读内置资源」与「可写用户数据」两套路径；引擎读数据时

readJSONAnywhere() 先看用户目录、没有再退回内置（asar 内也能读）。

b) 界面代码一行没改。 主进程起本地 http 服务、BrowserWindow 载入该地址 ——

不用 file://，前端 fetch('/api/...') 和流式生成就原样可用。这是当初把界面做成

「本地 Web UI」而不是「直接操作 DOM 的桌面应用」换来的好处。

c) 自检模式。 Electron 的窗口状态在命令行里看不到。于是加了 CIALLO_SELFTEST=1：

启动 2.5 秒后把窗口标题、URL、渲染层查询结果（.pool-item 数量、顶栏文字、页签数）

打成一行 JSON 到 stdout 再退出。check-desktop.js 就靠这行 JSON 断言打包后的程序真能用，

而不是只检查文件存在。

这一轮踩的坑

ELECTRON_RUN_AS_NODE 从环境继承。 第一次 electron . 直接崩：

TypeError: Cannot read properties of undefined (reading 'isPackaged') ——

这个变量存在时 electron.exe 会退化成纯 Node 模式，require('electron') 拿不到 API，

app 就是 undefined。测试脚本与打包脚本都要显式清掉。

npm 的 postinstall 没跑。 npm install electron 装好了包，但 dist/electron.exe

是 0 字节、path.txt 不存在 —— 二进制根本没下（ignore-scripts 查出来是 false，

更像是那次脚本阶段静默失败）。手动 node node_modules/electron/install.js

配上 ELECTRON_MIRROR 才把 234.9 MB 拉下来。装完必须验 dist/electron.exe 体积，

只看 package.json 的版本号会以为装好了。

npm.ps1 被执行策略拦住。 这台机器上 npm install 直接报「禁止运行脚本」，

绕过方式是 node D:\node_modules\npm\bin\npm-cli.js install ...，不碰 .ps1 包装。

签名 ≠ 有证书。 构建日志里一串 signing with signtool.exe，但没配证书时只是走个过场；

产物仍是未签名的，别人首次运行会撞 SmartScreen。

三条经验：

  • 断言要写成「属性」而不是「快照」。比如「heat 2 不出现器官名词」比「输出等于某段文本」耐用得多 —— 后者每改一个词库就红。

4. 已知限制

诚实地列出来，都是设计取舍或还没做到位的：

  • 长文重复度：池子总量决定了单篇的上限。目标 2000 字以内很干净；冲到 5000 字以上，

压力/高潮两族的句子会用完，此时引擎停止补写而不是复用 —— 字数会不足目标。

解法是继续扩池子，不是改逻辑。

  • 身体部位归属：{body} 抽出来的部位默认属于「对方」（B）。遇到「A 含住 B 的 X」

这类句式正确，但遇到反向动作（B 对 A 做）会错位。目前靠模板措辞规避。

  • 地点名与介词搭配：{loc} 直接内插，S14 的「便利店 · 后巷」会产出「便利店 · 后巷里那点空气」这种稍生硬的表达。
  • 同性别卡司：两位女性角色的场景里，代词无法区分，只能靠名字。

这是中文的固有限制，不是 bug。

  • 热度 5 的搭配：词库是按「部位 × 动作」独立抽样的，偶发不自然的组合（例如某些体位词组）。

缓解方式是加权重，或把这类句式拆成更小的单元。

  • 文本引擎不接 LLM：所有文字来自模板组合。想要真正的长程连贯性需要接模型，

引擎已经把 {line} / {voice} 这类接口留好了。
